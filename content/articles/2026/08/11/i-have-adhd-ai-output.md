# i-have-adhd：让 AI 编程助手直接说人话的开源技能

上周我在 GitHub 刷到一个特别有意思的开源项目 —— [i-have-adhd](https://github.com/ayghri/i-have-adhd)，一个专为 Claude Code 设计的输出格式技能。

用了一次我就把它留下来了：以前 Claude Code 回答问题，总免不了一段铺垫、几句总结，最后还要加一句"希望这能帮到你！"。装上这个技能之后，它第一行就告诉你该运行什么命令，步骤都编好号，结尾直接给下一步，一点废话都没有。

这篇文章讲清楚三件事：1）它到底解决了什么问题，为什么值得装；2）一分钟安装教程；3）这 10 条规则对我们日常使用 AI 有什么启发。

---

## 你有没有遇到过这个痛点？

让我们看一个对比，你就知道它好在哪里了。

**装之前：AI 传统回答方式**
```
好问题！让我想一想。你的身份验证流程包含几个环节：中间件、令牌验证和 Cookie 处理。
查看 `src/auth.ts` 后，`verifyToken` 函数（大约第 42–58 行）似乎使用了旧版 `jsonwebtoken` API。
一种做法是升级这个包并重写该函数。完成修改后，你需要运行身份验证测试，确认没有破坏任何功能。
顺便一提，你可能还想整体检查一下依赖版本。希望这能帮到你！如果你想进一步研究，请告诉我。
```

**装之后：i-have-adhd 模式回答**
```
运行 `npm install jsonwebtoken@latest`，然后编辑 `src/auth.ts:42`。

1. 打开 `src/auth.ts`
2. 将 `verifyToken`（第 42–58 行）替换为下面的代码片段
3. 运行 `npm test -- auth.spec.ts`

下一步：如果有测试失败，请粘贴第一行报错。
```

区别太大了。

传统 AI 回答符合"好好先生"的社交礼仪，但对 *已经坐在电脑前准备干活* 的你来说，这些铺垫和结束语完全是噪音 —— 你得从一大段文字里把真正要执行的步骤挖出来，滚动好几次才能找到命令。

而 i-have-adhd 模式从第一行就是行动，所有步骤编号，结尾直接给下一步，ADHD 大脑也能一秒接住。

> 项目 README 说的好：**对 ADHD 友好的输出。无需确诊 ADHD！**

哪怕你没有 ADHD，只要你用 AI 来写代码、解决实际问题，这个输出风格都能让你的效率至少提升一倍。

## 它的 10 条核心规则

这个项目的核心就是 10 条简单规则，每条都击中了当前 AI 输出的通病：

1. **先说下一步行动** — 第一行就给可执行的命令，不铺垫
2. **多步骤任务必须编号** — 每个步骤一个动作，不合并
3. **以一个具体的下一步结束** — 不说"有问题随时问"，直接说下一步该做什么
4. **避免离题** — 一个问题解决了再说下一个，不顺便给你挑一堆其他毛病
5. **每轮都重述当前状态** — "步骤 3 完成，schema 已更新"，不会让你记着进度
6. **给出明确的时间估计** — 不说"一会儿"，说"大约 15 分钟"
7. **让成果清晰可见** — 直接说"现在登录可以用魔法链接了"，不藏在总结里
8. **客观陈述错误** — 不说"哎呀出问题了"，直接说"测试在第 42 行失败，原因：缺失请求头，修复方法：..."
9. **每个列表最多 5 项** — 超过 5 项就分类，不堆在一起
10. **不要开场白、回顾和客气话** — "Great question"、"Hope this helps" 全部删掉

这 10 条规则本质上不是"让 AI 变短"，而是**把阅读者的工作记忆容量考虑进去了**。

项目文档里有一段话写得特别准：

> 五个事实驱动每一条规则：
> 1. 工作记忆很小，不在屏幕上的东西就是被忘了
> 2. 知道答案不等于做完答案，"明白了"和"做完了"之间的摩擦力，就是工作夭折的地方
> 3. 开始是最难的一步，第一个行动必须明显、微小、现在就能做
> 4. 模糊的时间估计等于没有估计，"一会儿"和"一下午"在感觉上是一样的
> 5. 多巴胺很稀缺，可见的进步才有用，埋在文字里的成果等于没成果

## 一分钟安装教程

### Claude Code 插件市场安装（推荐）

直接在 Claude Code 里输入：
```
/plugin install ayghri/i-have-adhd
```

然后你就能用了。调用方式：
```
/i-have-adhd
```

之后所有回答都会遵循这个模式，直到你输入：
```
stop adhd mode
```

### 手动安装（如果你用其他编辑器/Agent）

如果你用的不是 Claude Code，可以直接把规则复制到你的系统提示词里：

1. 访问 [项目仓库](https://github.com/ayghri/i-have-adhd)
2. 复制 `skills/i-have-adhd/SKILL.md` 的规则部分
3. 粘贴到你的 Agent 系统提示词末尾

核心规则就 10 条，不到 500 字，不会占用太多上下文。

---

## 自定义调整

Fork 这个仓库，编辑 `skills/i-have-adhd/SKILL.md` 就能改成你喜欢的风格。然后替换你本地的版本：

```bash
claude plugin uninstall i-have-adhd
claude plugin marketplace remove i-have-adhd
claude plugin marketplace add <你的用户名>/i-have-adhd
claude plugin install i-have-adhd@i-have-adhd
```

重启 Claude Code 就生效了。

## 谁该装这个技能？

**推荐安装：**
- 用 Claude Code 写代码解决实际问题
- 经常觉得 AI 回答太啰嗦，找半天找不到下一步
- 注意力容易被冗余信息分散，喜欢开门见山
- 跟 AI 合作时，经常忘记现在走到哪一步了

**可不装：**
- 你主要用 AI 写文章、写方案，需要它铺垫和扩展
- 你喜欢自己整理步骤，AI 只需要给你思路
- 你对当前的输出风格很满意

## 总结

i-have-adhd 不是什么大项目，代码（其实就是规则）只有 2KB，但它击中了当前 AI 输出的一个普遍问题——**AI 学了人类的社交礼仪，却忘了用户坐在电脑前是来干活的，不是来聊家常的**。

它给我的启发是：好的 AI 输出，不在于越详细越好，而在于**让用户能马上开始行动**。第一行就给下一步，比十句铺垫都有用。
